## Why

Mobile #2 (`shared-resources-moko-bootstrap`, PR [#116](https://github.com/aditrioka/nearyou-id/pull/116), squash-merged 2026-05-27) shipped Moko Resources after a proposal-phase comparison that rated Moko ≈ CMP Resources. A pre-implementation re-check on 2026-05-28 (one day post-archive) — performed under the freshly-shipped "Pre-implementation library re-check" rule in [`openspec/project.md`](../../project.md) § Change Delivery Workflow (PR [#118](https://github.com/aditrioka/nearyou-id/pull/118), squash-merged 2026-05-28) — surfaced material ecosystem shifts that would have flipped the original call: CMP 1.10.0 (Jan 2026) is production-stable with unified `@Preview` + Navigation 3 + stable Compose Hot Reload, CMP 1.11.0 (May 2026) ships further iOS interop maturity (native iOS text input, concurrent rendering default, Skia M144) — no resources-subsystem-specific changes in 1.11, but the overall CMP iOS layer continues to harden; note 1.11 raises iOS minimum to 14.0 so the project's iOS deployment target needs to be ≥14 (verify at apply time), and JetBrains has clearly committed to `compose-components-resources` as THE built-in CMP resources path going forward (vs. Moko Resources, which remains a community-maintained 0.x line — still active, not deprecated, but no longer the JetBrains-canonical path). The coordinate is **already pinned** in [`gradle/libs.versions.toml`](../../../gradle/libs.versions.toml) line 61 via the existing `composeMultiplatform = "1.10.3"` version variable but is currently unused — this change activates it and removes Moko. Migration cost is at its global minimum NOW: 10 strings, 2 SVG images, 1 variable-weight font, ~4 call sites in [HomeScreen.kt](../../../mobile/app/src/commonMain/kotlin/id/nearyou/app/screens/home/HomeScreen.kt) + 1 comment line in [HomeScreenTest.kt](../../../mobile/app/src/commonTest/kotlin/id/nearyou/app/HomeScreenTest.kt), 2 `build.gradle.kts` files, and a documentation-wording pass. Mobile #3 (`mobile-auth-google-signin-flow`), #4 (`mobile-age-gate-screen`), and #5 (`mobile-nearby-timeline-screen`) will collectively add 80-150+ strings within ~4 weeks; migrating then would cost 5–10× more. Doing this swap as the next mobile change (Mobile #2.5, interstitial before Mobile #3) is the cheapest moment that will ever exist. The swap also eliminates Mobile #2's dual-`mokoResources`-plugin workaround for the iOS framework copy task (the 7-line comment block at [`mobile/app/build.gradle.kts:8-14`](../../../mobile/app/build.gradle.kts:8) becomes obsolete with CMP Resources' native iOS framework integration).

## Capabilities

### New Capabilities

(None — this change is a substrate swap on existing capabilities, not introducing new behavior.)

### Modified Capabilities

- `shared-resources`: resource accessor surface changes from Moko `MR.strings.X` / `MR.images.X` / `MR.fonts.X` to CMP `Res.string.X` / `Res.drawable.X` / `Res.font.X`; resource directory convention changes from `commonMain/moko-resources/MR/base/` + `/images/` + `/fonts/` to `commonMain/composeResources/values/` + `/drawable/` + `/font/`. Non-resource surface (brand color tokens, typography, extension properties via CompositionLocal) is preserved bit-for-bit. Strings/images/font CONTENT unchanged — only the API to access them and the on-disk layout shift.
- `mobile-app-scaffold`: `HomeScreen` consumes `Res.string.*` / `Res.drawable.*` instead of `MR.strings.*` / `MR.images.*`. Same rendering behavior, same visible content. The "no hardcoded UI strings" convention text updates from "Moko Resources" to "Compose Multiplatform Resources" — the invariant itself is preserved.

**Header renames (MODIFIED-with-changed-header pattern):** 3 requirement headers in the `shared-resources` capability delta carry intentional rename-via-MODIFIED (the existing `### Requirement:` text gets updated text in the new delta — `openspec validate --strict` passes; the rename is captured by the MODIFIED-block-identity at archive time). The 3 renames are: `"Shared resources Gradle module exists with Moko Resources plugin"` → `"…with Compose Multiplatform Resources"`; `"Reuse existing Compose Multiplatform material3 pin; add only moko-resources pin"` → `"…remove moko-resources pin"`; `"Moko app_name string coexists with platform-native Android strings.xml app_name"` → `"app_name string coexists…"` (drop the `Moko ` prefix). The other 6 MODIFIED headers in the delta match canonical exactly.

**Canonical requirements preserved unchanged (NOT in the delta):** 5 requirements in `openspec/specs/shared-resources/spec.md` survive the swap without modification because they're Moko-agnostic in substance: `Brand color scheme exposed as NearYouColorScheme` (pure Compose data), `Reserved-purpose accents exposed as ColorScheme extension properties` (CompositionLocal pattern), `App launcher icon replaces wizard-default assets with NearYouID-branded variants` (platform-native Android adaptive icon + iOS Asset Catalog, independent of Moko), `ColorScheme extension properties throw outside NearYouTheme scope` (Compose semantics), `shared:resources namespace does not collide with mobile:app` (Android library namespace, independent of resource-codegen path). The MODIFIED delta only touches the 9 requirements that genuinely change; the 5 listed here remain canonical as-is post-archive.
