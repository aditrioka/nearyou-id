## Why

The chat schema (V14) ships `chat_messages.embedded_post_id`, `embedded_post_snapshot JSONB`, and `embedded_post_edit_id` as **null-only, forward-compatible** columns; the empty-message CHECK already permits embed-only messages; and `chat-realtime-broadcast`'s `ChatMessageBroadcast` already serializes the three `embedded_*` keys (null today). No surface populates them — sharing a post into a DM, the social loop the schema was explicitly built for, does not yet exist. Three shipped specs (`chat-conversations`, `chat-realtime-broadcast`, `mobile-chat`) name **`chat-embedded-posts`** by name as the future owner of this work, and the `embedded_post_edit_id → post_edits(id)` FK was deferred only until `post_edits` shipped — which it did at V22. This change closes that gap end-to-end and unblocks Phase 4 #14 (chat context-card edit-history navigation).

## What Changes

- **Backend send-path** — `POST /api/v1/chat/{conversation_id}/messages` accepts an optional `embedded_post_id` alongside the existing `content` (content becomes optional when an embed is present; the empty-message CHECK already allows this). When present the server resolves the post **for the sender as viewer** through the shipped visibility rules — bidirectional `user_blocks` NOT-IN join, `visible_posts` shadow-ban view, and `display_location`/fuzzed location **only** — then builds a self-contained `embedded_post_snapshot` JSONB (author handle + display name, content, `cityName`, `createdAt`, `editedAt`) and sets `embedded_post_edit_id` to the post's latest `post_edits.id` (NULL if never edited) as the "version-at-share-time" anchor. A post the sender cannot see (blocked / shadow-banned / non-existent / soft-deleted) is rejected with the project's constant-404 idiom (forbidden indistinguishable from non-existent).
- **Flyway V37** — (a) add the previously-deferred FK `chat_messages.embedded_post_edit_id REFERENCES post_edits(id) ON DELETE SET NULL` via the `ADD CONSTRAINT … NOT VALID` + `VALIDATE CONSTRAINT` pattern (V9/V16 precedent), bringing the live DB in line with the canonical `chat_messages` schema in `docs/05-Implementation.md` § Direct Messaging; (b) add `CHECK (octet_length(embedded_post_snapshot::text) < <limit>)` — `chat-realtime-broadcast` § "Embedded-payload size cap" explicitly assigns this enforcement to this change — sized to keep the broadcast payload within Supabase Realtime's per-message budget.
- **Realtime** — the publish leg now emits **populated** `embedded_*` fields for an embed message (serialization is already forward-compatible). The null-only invariant flips to present-and-null for plain messages, populated for embed messages.
- **Mobile** — a **"Bagikan ke chat"** affordance (post-detail) opens a conversation picker, reuses the shipped `createOrReturnConversation(recipientUserId)` create-or-return path, and sends with `embedded_post_id`. The chat thread renders an embed message as a **context card** from `embedded_post_snapshot` (author, content, city — never coordinates); tapping it navigates to the current post detail; a **"diedit sejak dibagikan"** banner shows when the live post's latest edit differs from the message's `embedded_post_edit_id`; a hard-deleted source post (snapshot present, `embedded_post_id` null) renders the snapshot in a **"post telah dihapus"** state with no navigation. All strings via Compose Multiplatform Resources.

## Capabilities

### New Capabilities
- `chat-embedded-posts`: Backend send-path that accepts `embedded_post_id`, resolves the post visibility-respecting (block / shadow-ban / spatial-fuzzing), persists a self-contained `embedded_post_snapshot` + `embedded_post_edit_id` version anchor, enforces a snapshot size cap, and adds the V37 FK + CHECK migration.
- `mobile-chat-embedded-posts`: Mobile share-a-post-to-chat entry point + conversation picker, plus the chat-thread context-card render — snapshot display, tap-to-current-post navigation, edit-since-shared banner, and hard-deleted-post snapshot state.

### Modified Capabilities
- `chat-conversations`: The `embedded_post_edit_id` FK is no longer deferred — V37 ships it; the "FK remains deferred post-V16" scenario flips to a "FK is live" assertion, and a snapshot size CHECK is added to the schema.
- `chat-realtime-broadcast`: The "three embedded fields SHALL be null for every payload" requirement flips to populated-for-embed-messages; payload-size verification (paired with the V37 CHECK) lands here.
- `mobile-chat`: The "Send body carries no embedded fields" requirement flips — the send body MAY carry `embedded_post_id`; and the `ChatRealtimeSubscriber` / `ChatMessageInbound` model that currently drops the three `embedded_*` keys now surfaces them so the thread can render the card (still vendor-SDK-free).

## Impact

- **Code**: backend chat send handler + a post-snapshot resolver/service + repository read (backend layering per `docs/11` § Pattern Registry); `:infra:supabase-realtime` `ChatMessageInbound` gains the embedded fields (parsed at the infra boundary, no vendor symbol leaked); `:mobile:app` chat-thread UI (context card) + post-detail share affordance + conversation picker; new `Res.string.*` entries.
- **Schema / migrations**: **V37** (next free after #417's pending V36; `git mv` up if taken at apply-time) — the deferred `embedded_post_edit_id` FK + the `embedded_post_snapshot` size CHECK. No new table.
- **Docs (amend, same PR)**: `docs/05-Implementation.md` § Direct Messaging — Chat Message Schema (Embedded Post) is amended to add the new embedded-snapshot size CHECK to the canonical `chat_messages` block (the doc already shows the `embedded_post_edit_id` FK live, so V37 only adds the CHECK). This keeps the `chat-conversations` "match docs/05 verbatim" requirement true rather than introducing schema the canonical doc omits.
- **APIs**: `POST /api/v1/chat/{conversation_id}/messages` gains an optional `embedded_post_id`; the Realtime broadcast payload's existing `embedded_*` keys become populated. No breaking change (additive; existing `{ content }` sends are unaffected).
- **Invariants touched** (cited in `design.md`): spatial fuzzing (`display_location` only — no raw coords in the snapshot, the single biggest risk), bidirectional block exclusion (`BlockExclusionJoinRule`), shadow-ban `visible_posts` read, no vendor SDK import outside `:infra:*`, content-length guards unaffected.
- **Layers (per `docs/12` cross-layer cohesion)**: full vertical slice — **backend + realtime + mobile**. No admin layer is required: moderation of an embedded post already flows through the shipped chat-message redaction (`admin-chat-message-redaction`) and the source post's own report/moderation path; the admin post-edit-history viewer is a separate in-flight surface.
- **Visual reference**: the chat-thread mockup frame (`dev/mockups`, `docs/11` § 2.8) for the context-card layout; binding rule `docs/11` § 2.8.
