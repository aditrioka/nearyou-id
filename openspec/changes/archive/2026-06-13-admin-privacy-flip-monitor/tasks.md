## 4. Filter parsing (lenient + parameterized)

- [x] 4.1 Parse `status` against the allowed set `{in_window, overdue}`; an unrecognized/over-long value is ignored (lenient), other filters still apply. `in_window` → append `AND ? < privacy_flip_scheduled_at`; `overdue` → append `AND privacy_flip_scheduled_at <= ?`, binding the SAME `eval_instant` parameter as the classification `CASE` (design D3) so the filtered set matches the rendered classes at the boundary.

## 6. Tests

- [x] 6.1 Authenticated GET renders the table with a pending-flip row's `username` + status + base-layout sections; unauthenticated GET → 302 `Location: /admin/login`.
- [x] 6.2 A user with `privacy_flip_scheduled_at IS NULL` is excluded; a soft-deleted user (`deleted_at IS NOT NULL`) with a non-NULL `privacy_flip_scheduled_at` IS included (design D6 — the no-deleted_at-filter assertion).
- [x] 6.3 Classification: a future-dated flip → IN_WINDOW (with time-remaining); a past-dated flip → OVERDUE (with overdue-by); both buckets appear together when unfiltered. Tests inject a FIXED `Clock` and pin `privacy_flip_scheduled_at` at explicit offsets relative to that injected `eval_instant` (never CI-host-local wall-clock) so the boundary is deterministic across runners.
- [x] 6.3c Boundary fencepost: with an injected fixed clock, seed a row whose `privacy_flip_scheduled_at` EQUALS `eval_instant` exactly → classified OVERDUE (strict `>` for IN_WINDOW). AND no-skew: that same boundary row appears under `status=overdue` and is excluded under `status=in_window` (one `eval_instant` drives both class and filter — design D3, the central anti-skew guarantee).
- [x] 6.4 Ordering: an OVERDUE row (deadline in the past) sorts ahead of an IN_WINDOW row (deadline in the future) — ascending `privacy_flip_scheduled_at`.
- [x] 6.5 Keyset pagination: page capped at page size + "next" control present; following the cursor returns a strictly-later, non-overlapping page; malformed cursor → 200 first page; last page omits the "next" control.
- [x] 6.5a Exact page-size boundary (fencepost): seed EXACTLY page-size rows → full page rendered AND NO "next" control; then page-size + 1 rows → first page-size rendered AND "next" control present.
- [x] 6.5b `id`-tiebreaker on identical `privacy_flip_scheduled_at`: seed ≥2 rows with the SAME `privacy_flip_scheduled_at` but distinct `id`s straddling a page boundary → page through and assert each appears exactly once (no skip, no duplicate) via the `(privacy_flip_scheduled_at, id) > (?, ?)` `id ASC` tiebreaker.
- [x] 6.6 `status` filter: `status=overdue` renders only OVERDUE rows; `status=in_window` renders only IN_WINDOW rows; an unrecognized `status` is ignored while `q` still applies.
- [x] 6.7 `q` search: exact case-insensitive username match returns the single user; a UUID-shaped `q` filters `id`; `status` + `q` compose with AND (a `q`-matched but wrong-`status` user → empty state); an empty/whitespace-only `q` is ignored (unfiltered list, NOT an empty-username match); a 60-char username matches exactly while a 61-char `q` is bounded out (no truncation of a legitimate max-width username).

- [x] 6.10 HTMX vs plain-GET: `HX-Request: true` → `#privacy-flips-table` fragment only (no `<html>`/header/footer); plain GET → full page with the fragment + filter reflected; filtered URL is shareable.
