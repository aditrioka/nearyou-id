## 2. Repository — `UserModerationRepository`

- [x] 2.1 Create `UserModerationRepository(dataSource: DataSource)` in the `:backend:ktor` `admin` package (parameterized queries only; the admin module is exempt from the `visible_*`-view + block-exclusion lint, so direct `FROM users` is allowed here).
- [x] 2.2 `lookup(q: String)`: resolve `q` as a user UUID first (by primary key), else attempt an EXACT, case-sensitive `users.username` match; return a small DTO (`id`, `username`, `is_banned`, `suspended_until`, `deleted_at`) or `null`. Parameterized. (Spec: "User lookup resolves by UUID then exact username".)
- [x] 2.3 `suspend(targetId, actingAdminId, reason, ip, userAgent)`: ONE transaction (`autoCommit = false`) — `SELECT ... FOR UPDATE` the current `is_banned` / `suspended_until` / `deleted_at`; apply the D7 eligibility guard (reject soft-deleted; reject `is_banned = TRUE AND suspended_until IS NULL` permanent ban — no downgrade; the "already suspended" branch keys on `suspended_until IS NULL`, NOT `> NOW()`, so an elapsed-but-unswept window is re-suspendable); on eligible, `UPDATE users SET is_banned = TRUE, suspended_until = NOW() + INTERVAL '7 days'`; INSERT the `user_suspended` audit row + the `account_action_applied` notification row in the SAME transaction; commit. Return a typed outcome (`Applied` / `RejectedSoftDeleted` / `RejectedPermanentBan`). (Specs: suspend apply, suspend reject, audit, notification, atomicity.)
- [x] 2.4 `unban(targetId, actingAdminRole, actingAdminId, reason, ip, userAgent)`: ONE transaction — `SELECT ... FOR UPDATE`; if `is_banned = FALSE` → `NoOpNotBanned` with NO writes (no audit row); if the target is permanently banned (`suspended_until IS NULL`) AND `actingAdminRole = moderator` → `ForbiddenPermanentBan` with NO writes (the D3 permanent-ban tier, checked inside the tx); else `UPDATE users SET is_banned = FALSE, suspended_until = NULL` + INSERT the `user_unbanned` audit row in the same transaction; commit. Return a typed outcome (`Applied` / `NoOpNotBanned` / `ForbiddenPermanentBan`). (Specs: unban, role gate, audit, atomicity.)
- [x] 2.5 Build `before_state` / `after_state` JSON in Kotlin (kotlinx.serialization) as `{"is_banned": <bool>, "suspended_until": <ISO-8601 Instant | null>}` per design D6; capture the PRIOR `suspended_until` in `before_state` (the re-suspend reset case). Tests assert `suspended_until` by parsed-`Instant` value-equality, not string match.
