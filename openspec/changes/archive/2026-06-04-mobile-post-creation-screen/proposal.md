## Why

`:mobile:app` can already authenticate, age-gate, read the Nearby feed, and resolve device location — but it **cannot create a post**. A location-based social app that can read nearby posts but not write them is a half-loop. This change ships the missing write half: the first content-creation screen, a thin Compose Multiplatform client over the **already-shipped** backend `POST /api/v1/posts` ([`openspec/specs/post-creation/spec.md`](../../specs/post-creation/spec.md)). It is the change the archived `mobile-location-permission-flow` proposal forward-references by this exact name ("The post-creation location picker → `mobile-post-creation-screen`"), and it fulfils the [`docs/08-Roadmap-Risk.md`](../../../docs/08-Roadmap-Risk.md) Phase 3 Shared-KMP line "Post creation + location picker + content length guard". With the mobile/admin scaffolding menu now fully merged, this is the highest-impact next step toward a demoable MVP: it closes the create→read core loop.

## What Changes

- **New `PostCreationScreen`** (Voyager `Screen`) — a Material 3 composer: a multiline content field, a live `N/280` character counter, an outcome-driven error banner, and a "Posting" CTA. It mirrors the house pattern (`mobile-age-gate` / `mobile-nearby-timeline` / `mobile-auth-signin`): a layered `PostCreationApiClient → CreatePostRepository`/`CreatePostFlow` interface → pure Compose-free `PostCreationUiState` + projection → screen, Koin-wired behind a testable flow seam, every string via `:shared:resources`.
- **Calls the shipped `POST /api/v1/posts`** with `{ content, latitude, longitude }`. The Bearer token + 401 refresh are handled by the shipped `HttpClient` `Auth` plugin (NOT reimplemented). The client keys user-facing messages on the backend `error.code` (`content_empty` / `content_too_long` / `location_out_of_bounds` / `content_moderated_profanity` / `invalid_json`) — a departure from the Nearby repository, which keyed only on HTTP status. (Reconciliation note: `content_moderated_profanity` is defined in the `post-creation` spec § "Verdict.Reject" — with its canonical Bahasa message, which `post_create_error_moderated` reuses — but is omitted from that spec's older § "Error envelope" "exactly these codes" enumeration; the mobile side is correct, and the upstream spec inconsistency is logged to `FOLLOW_UPS.md`, not fixed here.)
- **Automatic-location-only** (now the product requirement): the post coordinate is acquired at submit time from the already-shipped `LocationProvider.current()`; a `LocationUnavailableException` (permission not granted / no fix) maps to an "enable location" state with a "Buka Pengaturan" CTA. **No map SDK and no manual-pin** — `docs/02-Product.md` § 2 was narrowed to automatic-only by [#144](https://github.com/aditrioka/nearyou-id/pull/144), so manual location selection is **out of scope (dropped), not deferred**. No new `gradle/libs.versions.toml` entry (no substrate change).
- **Composer entry point**: a `FloatingActionButton` on the home surface opens the composer (Voyager `push`); on success it pops back. Placed at the `HomeScreen` level so `mobile-nearby-timeline` stays unmodified (design Decision; nested-Scaffold accepted for MVP, consolidated by the future tab-host change).
- **New Bahasa Indonesia strings** in `:shared:resources` (composer title, content placeholder, char-counter format, "Posting" CTA, loading, and the per-`error.code` + location-unavailable messages). `docs/03-UX-Design.md` has no composer copy section, so these are derived BI copy consistent with the Mobile #3/#4/#5 register, flagged for UX review.
- **Test coverage** mirroring `mobile-nearby-timeline`: a Robolectric `PostCreationScreenTest` (added to the Release-variant `*ScreenTest` exclude), a commonTest `PostCreationUiStateTest` (pure projection incl. Unicode code-point counting), and MockEngine `PostCreationApiClient` / `CreatePostRepository` tests.

**Out of product scope** (dropped, NOT deferred — no follow-up): manual map-pin / manual location selection, per [#144](https://github.com/aditrioka/nearyou-id/pull/144) narrowing `docs/02-Product.md` § 2 to automatic-only.

**Deferred to named follow-ups**: image attachment (Phase 4, `image_upload_enabled`-gated); any post daily-quota / rate-limit UI (no backend post rate-limiter exists today); the Premium 30-minute edit window; auto-refreshing the Nearby feed to show the new post on return (`mobile-post-creation-refresh-nearby-on-return`); composer iOS flow-test parity (`mobile-post-creation-ios-flow-tests`); the Home tab-host (Nearby/Following/Global + shared FAB) consolidation.

## Capabilities

### New Capabilities
- `mobile-post-creation`: the mobile content-creation surface — a commonMain `PostCreationApiClient` over the shared `HttpClient` calling `POST /api/v1/posts`, a `CreatePostRepository` behind a `CreatePostFlow` seam that acquires the device coordinate and maps HTTP status + `error.code` to a sealed `PostCreationOutcome`, a pure `PostCreationUiState` projection (char count, over-limit, submit-enabled, loading, success, per-error banner), the `PostCreationScreen` composer, the home-surface FAB entry point, and the new Bahasa Indonesia copy. Enforces PII discipline (the post body coordinate is never logged and the echoed actual coordinate is never rendered) and the mobile-strings invariant.

## Impact

- **Module**: `:mobile:app` (new `post/` + `screens/post/` packages in commonMain; `HomeScreen` gains the FAB + Voyager push; `MobileModule` gains three bindings; `build.gradle.kts` Release-variant test-exclude gains the new `*ScreenTest`). `:shared:resources` (new strings + the `SharedStringsCatalogTest` count bump from 36).
- **Backend**: none — consumes the already-shipped `POST /api/v1/posts` (`post-creation` capability). No migration, no new endpoint.
- **Dependencies**: none new — reuses the platform-bound `LocationProvider` (`play-services-location` on Android / `CLLocationManager` on iOS, both already shipped by `mobile-location-permission-flow`) and the shared `HttpClient`. No `gradle/libs.versions.toml` change.
- **Privacy / invariants**: the device coordinate travels in the POST **body**, so the change MUST keep `LogLevel.HEADERS` (bodies are not logged at HEADERS) and MUST NOT widen logging to BODY/ALL; the success path MUST NOT render the echoed actual `latitude`/`longitude`; the mobile-strings invariant (no hardcoded UI strings) applies to all new copy.
- **Verification**: platform location actuals are not unit-testable in commonTest; a manual Android-device + iOS-sim post-creation pass (incl. the location-denied path) is the runtime check, alongside the Robolectric/commonTest/MockEngine suites.
