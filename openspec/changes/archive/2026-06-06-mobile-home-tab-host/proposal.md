## Why

The mobile home is the central navigation spine of the user-facing app, and [`docs/02-Product.md`](../../../docs/02-Product.md) § Timeline Features specifies it as **three tabs: Nearby, Following, Global**. Today `HomeScreen` is a thin host that renders only `NearbyTimelineScreen` + the composer FAB — its own KDoc forward-references "a future tab-bar change makes this the Nearby/Following/Global host", and the deferred [`FOLLOW_UPS.md`](../../../FOLLOW_UPS.md) entries `mobile-home-tab-host` + `mobile-timeline-empty-global-cta` both park their work on this change. The backend Global feed (`GET /api/v1/timeline/global`) has shipped and sits unconsumed by mobile. This change builds the tab host and lights up the Global tab with that live feed — the onboarding entry-point surface ("*Global is the entry point*", `docs/02-Product.md`) — completing the home navigation shell and giving the app a never-empty, demoable second feed.

## What Changes

- **Nearby/Following/Global bottom-nav tab host.** `HomeScreen` becomes a Material 3 `NavigationBar` host whose body renders the selected tab's screen **directly under the `HomeRoute` scope**. Selected tab is a `@Serializable` `Tab` enum held in `rememberSaveable` (iOS-safe). Per-tab `NavDisplay` back stacks are **deferred** to the first intra-tab destination (post detail / profile) — there is no intra-tab navigation yet, so building them now would be vestigial; this change adds no new tab-root `NavKey`s. (Nav-model decision A, resolved at proposal review.)
- **The composer FAB stays at the home level** — one composer affordance shared across all three tabs (existing design D6). `PostCreationRoute` is pushed onto the **root** back stack (above `HomeRoute`) so the composer covers the whole surface including the tab bar.
- **Global tab — live feed.** New `GlobalTimelineScreen` + `GlobalTimelineViewModel` + `GlobalTimelineUiState` + `GlobalTimelineRepository` + `GlobalTimelineFlow` + `GlobalTimelineApiClient` mirroring the shipped Nearby plumbing, calling `GET /api/v1/timeline/global`. The response DTOs mirror the **shipped** `GlobalPostDto`/`GlobalResponse` wire (`TimelineRoutes.kt`) — identical to Nearby's mixed-case wire **minus `distanceM`** (Global has no spatial filter, so **no distance** is rendered; each card shows `city_name` under the author, content, created time, read-only `liked_by_viewer`/`reply_count`). Authenticated-only (guest Global is deferred upstream); reuses the existing singleton `SessionIdProvider` for the `X-Session-Id` soft-cap header.
- **Nearby tab — empty-state "lihat Global" CTA.** The Nearby empty state gains a CTA that switches to the Global tab (closes `mobile-timeline-empty-global-cta`; the `timeline_empty_nearby` copy already implies the affordance). Nearby feed behavior is otherwise unchanged.
- **Following tab — documented empty-state placeholder (feed DEFERRED).** The Following tab renders the documented empty-state placeholder ("*Following empty → arahkan ke Nearby/Global*", [`docs/03-UX-Design.md`](../../../docs/03-UX-Design.md) § Empty State) and **issues no `timeline/following` fetch**. The real Following feed is deferred — there is no follow-action UI on mobile yet, so the feed would be perpetually empty. The deferral is captured as explicit positive + negative-guard requirements so the follow-up `mobile-following-timeline-screen` has a requirement to MODIFY.
- **No new dependencies, no Flyway migration.** Navigation 3, Koin, the Ktor KMP client, `:shared:distance`, and Compose Multiplatform Resources are all already on the classpath and actively used; the backend endpoint already exists.

## Capabilities

### New Capabilities

- `mobile-home-tab-host`: The Nearby/Following/Global tab host in `:mobile:app` — a `NavigationBar` whose body renders the selected tab's screen directly under `HomeRoute`, tab selection via an iOS-safe serializable `Tab` enum, the home-level composer FAB shared across tabs, per-tab feed-state preservation (no re-fetch on switch), and the Following-tab deferred placeholder (positive render + negative no-fetch guard). Per-tab `NavDisplay` back stacks are deferred.
- `mobile-global-timeline`: The mobile Global-timeline feed surface — `GlobalTimelineScreen` + repository/flow/API-client seam calling `GET /api/v1/timeline/global`, DTOs mirroring the shipped distance-less Global wire, six-state screen mapping (loading/content/empty/error/hard-cap/soft-cap), PII discipline (no `author_user_id`, no raw coordinates, no distance), and `X-Session-Id` soft-cap accounting.

### Modified Capabilities

- `mobile-nearby-timeline`: `HomeScreen` no longer renders `NearbyTimelineScreen` as its direct body — `NearbyTimelineScreen` is now the **Nearby tab's** content within the tab host (composed directly under `HomeRoute`); the Nearby feed load state stays **`HomeRoute`-scoped** (VM-resolution unchanged from today) and now additionally survives tab switches as well as the composer round-trip; the Nearby empty state gains the "lihat Global" CTA. Routing target (`HomeRoute`) is unchanged.
- `mobile-post-creation`: The home-surface FAB requirement is updated — `HomeScreen`'s body is now the tab host (not `NearbyTimelineScreen` directly); the FAB still lives at the home level and pushes `PostCreationRoute`, now onto the root back stack so the composer overlays all tabs.

## Impact

- **Code (`:mobile:app` only):** `screens/home/HomeScreen.kt` (rework into the tab host); a `@Serializable` `Tab` enum (selected-tab state, `rememberSaveable`); new `screens/timeline/GlobalTimelineScreen.kt` + `GlobalTimelineViewModel.kt` + `GlobalTimelineUiState.kt`; new `timeline/GlobalTimelineApiClient.kt` + `GlobalTimelineFlow.kt` + `GlobalTimelineRepository.kt`; new `screens/timeline/FollowingPlaceholderScreen.kt` (or equivalent); a hoisted `onSeeGlobal` callback added to `NearbyTimelineScreen`; Koin wiring in `di/MobileModule.kt`; new Bahasa Indonesia strings in `:shared:resources` (tab labels, Following placeholder, Global title/loading/empty, "lihat Global" CTA). No new tab-root `NavKey`s (per-tab back stacks deferred).
- **Backend / API:** none (consumes the already-shipped `GET /api/v1/timeline/global`). **Schema:** none (zero Flyway migrations).
- **Dependencies:** none added (all substrate already pinned + actively used).
- **Docs / follow-ups:** deletes the `mobile-home-tab-host` + `mobile-timeline-empty-global-cta` `FOLLOW_UPS.md` entries on ship; adds a `mobile-following-timeline-screen` follow-up (deferred real Following feed) and a `mobile-home-tab-host-per-tab-backstacks` follow-up (deferred per-tab Nav3 back stacks, for the first intra-tab destination).
- **Out of scope (Non-Goals):** real Following feed; Nearby radius slider; infinite scroll; relative timestamps; Nav3 adaptive multi-pane scenes; analytics-consent / notifications / profile / chat screens; guest (unauthenticated) Global access.
