## Why

Mobile #1–#4 built a usable Google sign-in + 18+ signup flow that dead-ends at a placeholder `HomeScreen`. **This change ships the first product surface** — an authenticated user landing on the **Nearby timeline**: it calls the shipped `GET /api/v1/timeline/nearby`, renders each post with the shared `DistanceRenderer`, supports pull-to-refresh, and handles explicit loading / empty / error / rate-limit states. It is the "first demoable product flow" milestone in [`openspec/project.md`](../../project.md) § Mobile + Admin Scaffolding Priority (Mobile #5) — the last change gating the flip back to balanced priority — and the first end-to-end path that surfaces `display_location` to a client, against which the `coordinate-jitter` Phase 2 fuzzing audit (`docs/08-Roadmap-Risk.md` item 15) runs. The visual treatment it establishes becomes the pattern every later product screen inherits.

## What Changes

- **NEW: `NearbyTimelineScreen` (Voyager `Screen`) in `:mobile:app` commonMain** — the Nearby feed: a top bar ("*Post dari lokasi ini*"), a list of read-only post cards (content, `city_name`, `DistanceRenderer.render(distance_m)`, relative time, read-only like/reply counts), Material 3 pull-to-refresh, and explicit loading / empty / error / rate-limit-hard / rate-limit-soft states. Theme-aware under `NearYouTheme`; every string via `stringResource(Res.string.X)` (zero hardcoded literals).
- **NEW: networking + orchestration** — `NearbyTimelineApiClient` (`@Serializable` snake_case request/response DTOs incl. the optional `upsell` object) calling `GET /api/v1/timeline/nearby`; `NearbyTimelineRepository` (Koin singleton, seamed behind a `NearbyTimelineFlow` interface for fakes) mapping HTTP **status** → a sealed `NearbyTimelineOutcome` with no generic fallthrough; a pure Compose-free `NearbyTimelineUiState` + projection function (mirroring Mobile #4's `AgeGateUiState`).
- **NEW: `LocationProvider` seam (stubbed)** — a commonMain interface returning a `LatLng`; the default Koin binding is a `StubLocationProvider` yielding a fixed Jakarta coordinate `LatLng(-6.2, 106.8)` at a fixed **20 km** radius (the Free-tier default). Real device location, runtime permission, the UU-PDP consent modal, and the denial fallback are **DEFERRED** to a dedicated follow-up (`mobile-location-permission-flow`).
- **NEW: `SessionIdProvider`** — a per-app-process id sent as the `X-Session-Id` header so the backend's per-session soft-cap accounting works (rather than collapsing to the `no-session` bucket).
- **MODIFIED: `:shared:distance` becomes mobile-consumable** — adds `androidTarget()` + `iosArm64()` + `iosSimulatorArm64()` and provides `actual hmacSha256`/`unixMillis` for `androidMain` (javax.crypto) + `iosMain` (CommonCrypto `CCHmac` + `NSDate`). `JitterEngine`/`UuidV7`/`Crypto` expects stay in `commonMain` (required by the `coordinate-jitter` spec). The mobile app consumes only `DistanceRenderer.render` + `LatLng`; `JITTER_SECRET` never ships to clients.
- **MODIFIED: `HomeScreen` repurposed** — from the wizard placeholder to a thin host that renders `NearbyTimelineScreen` (sole content for now; a future tab-bar change makes it the Nearby/Following/Global host). `RootRouterScreen` routing is **unchanged** (still routes to `HomeScreen`), so `mobile-auth-signin` is untouched.
- **NEW: Bahasa Indonesia strings** in `:shared:resources` (`timeline_nearby_title`, `timeline_loading`, `timeline_empty_nearby`, `timeline_limit_hard`, `timeline_limit_soft`); the `home_placeholder_*` strings are no longer rendered (retained in the catalog, consistent with how `signin_error_no_account` was retained when Mobile #4 stopped rendering it — full removal is a future cleanup). Error/retry reuse the existing `signin_error_network` + `cta_retry`.
- **NO backend code, NO schema/migration, NO new library pins** — the `nearby-timeline` + `timeline-read-rate-limit` capabilities are shipped; Ktor client, kotlinx-serialization/datetime, Material 3, Voyager, and Koin are already on `:mobile:app`'s classpath; `:shared:distance` adds only KMP targets + platform-API crypto actuals (no `gradle/libs.versions.toml` change).

## Capabilities

### New Capabilities
- `mobile-nearby-timeline`: the mobile Nearby-timeline surface — `NearbyTimelineScreen` (+ `HomeScreen` host), `NearbyTimelineApiClient` (snake_case DTOs incl. optional `upsell`), `NearbyTimelineRepository`/`NearbyTimelineFlow` orchestration against `GET /api/v1/timeline/nearby`, the status-driven `NearbyTimelineOutcome` mapping + `NearbyTimelineUiState` projection, the `LocationProvider` stub (fixed Jakarta + 20 km), `SessionIdProvider` + `X-Session-Id`, `DistanceRenderer` consumption, all screen states (loading / content / empty / error / rate-limit-hard / rate-limit-soft) + pull-to-refresh, PII discipline, and the Koin `mobileModule` wiring.

### Modified Capabilities
- `coordinate-jitter`: the `:shared:distance` module gains `androidTarget()` + `iosArm64()` + `iosSimulatorArm64()` with `actual hmacSha256`/`unixMillis` on `androidMain` + `iosMain` (byte-identical to the JVM actual, verified by a new commonTest known-answer test); `JitterEngine`/`UuidV7`/`Crypto` expects remain in `commonMain` (now also compiled for the mobile targets). No jitter behavior changes; `JITTER_SECRET` stays server-only.
- `shared-resources`: the module gains a Nearby-timeline string set — `timeline_nearby_title`, `timeline_loading`, `timeline_empty_nearby`, `timeline_limit_hard`, `timeline_limit_soft` (additive; the existing foundational requirement is untouched). The `home_placeholder_title`/`home_placeholder_version` strings are no longer rendered (`HomeScreen` is repurposed) but are retained in the catalog, consistent with `signin_error_no_account`'s retention. No earlier string is altered; the "no hardcoded UI strings" grep-step verification stays.

## Impact

- **Code**: `:mobile:app` commonMain (`NearbyTimelineScreen`, `NearbyTimelineApiClient`, `NearbyTimelineRepository`/`NearbyTimelineFlow`, `NearbyTimelineUiState` + projection, `NearbyTimelineOutcome`, `LocationProvider`/`StubLocationProvider`, `SessionIdProvider`, `HomeScreen` repurpose, Koin `mobileModule`); `:shared:distance` build + `androidMain`/`iosMain` crypto actuals; `:shared:resources` strings.
- **APIs consumed**: `GET /api/v1/timeline/nearby` (shipped; snake_case wire contract per the `nearby-timeline` + `timeline-read-rate-limit` specs). No backend change.
- **Dependencies**: none added to `gradle/libs.versions.toml`. `:shared:distance` adds KMP targets + platform crypto actuals (javax.crypto on Android; CommonCrypto + Foundation on iOS); `kotlin.uuid.Uuid` (stdlib) for the session id.
- **Security surface**: first client read path that surfaces `display_location` (the Phase 2 fuzzing-audit target); `JITTER_SECRET` confirmed absent from the client binary (only the jitter *algorithm* ships, which the `coordinate-jitter` non-reversibility requirement permits); PII discipline (render only API-returned fields; never log tokens/coordinates).
- **FOLLOW_UPS.md**: adds `mobile-location-permission-flow` (real GPS + permission + consent modal + denial fallback), `mobile-nearby-radius-slider` (10/20/50/100 km slider + Free-bounce/Premium-pick), `mobile-nearby-timeline-infinite-scroll` (cursor pagination / load-more), and `mobile-timeline-empty-global-cta` (the empty-state switch-to-Global affordance, once a Global screen exists).
- **Out of scope**: real device location + permission flow; the radius slider; infinite-scroll pagination; the empty-state Global CTA; like/reply *actions* + post-detail screen; the Nearby/Following/Global tab bar; the Premium upsell deep-link (billing not built — `upsell` flags are surfaced as copy only).
