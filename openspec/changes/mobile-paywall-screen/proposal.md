## Why

The two shipped Premium upsell CTAs in `:mobile:app` are dead-ends: the `DailyCapUpsellDialog` "Aktifkan Premium" button (mockup frame 18) and the `SearchScreen` Premium-gate / rate-limit "Aktifkan Premium" CTA ([`SearchScreen.kt:318`](mobile/app/src/commonMain/kotlin/id/nearyou/app/screens/search/SearchScreen.kt:318)) both invoke a callback that only dismisses — no paywall destination exists. `mobile-cap-upsell-dialog` § "Premium CTA navigation is deferred" names this change as its explicit MODIFY hook; GitHub issues [#235](https://github.com/aditrioka/nearyou-id/issues/235) (keystone), [#254](https://github.com/aditrioka/nearyou-id/issues/254) (route search CTA), and [#253](https://github.com/aditrioka/nearyou-id/issues/253) (proactive upsell) all wait on it. Phase 4 (premium/payment) is in flight — the RevenueCat subscription backend ([PR #291](https://github.com/aditrioka/nearyou-id/pull/291)) is **merged** — so the conversion entry point is now the bottleneck, not the backend.

## What Changes

- **New `PaywallRoute` + `PaywallScreen`** (Compose Multiplatform / Material 3, mockup frame 17): a Premium hero, the Month-1 benefit set (features-available-now per the docs/03 disclosure rule — no image upload), three pricing cards (Weekly / Monthly / Yearly) with the frame-17 default-selected-Monthly + strike-anchor + savings-% treatment, a full-width "Aktifkan Premium" CTA, and the disclosure footer. Pushed onto the root back stack like `SearchRoute` / `PostDetailRoute`; carries an **entry-context** payload (which gated surface opened it) to tailor the hero, with no PII on the route.
- **New `:infra:revenuecat` module** wrapping the RevenueCat **Kotlin Multiplatform SDK** (`purchases-kmp-core`, stable v1) behind a vendor-SDK-free commonMain `PurchaseController` interface — Offerings fetch, purchase execution, and `CustomerInfo` entitlement check. The vendor dependency is `implementation`-scoped so the SDK never reaches `:mobile:app`'s compile classpath (invariant #16). Adds a `purchases-kmp` catalog pin and the module to `settings.gradle.kts`.
- **Pricing is read from RevenueCat Offerings at runtime, not hardcoded.** The displayed prices, the derived strike-through anchors (Monthly vs 4× Weekly; Yearly vs 12× Monthly), the savings percentages, and the Weekly per-day baseline are computed from the fetched package prices. The mockup governs the card layout; the package data governs the values (docs/11 §2.8 precedence).
- **Subscribe → return → re-evaluate**: the CTA drives `PurchaseController.purchase(...)`; on success the screen confirms the entitlement and pops, returning to the surface that opened it. The RevenueCat SDK flips `CustomerInfo` client-side immediately; `users.subscription_status` flips via the [#291](https://github.com/aditrioka/nearyou-id/pull/291) webhook (eventual) — the brief client-premium / backend-still-gated window is handled gracefully.
- **Fail-soft `Unconfigured` state**: until the RevenueCat dashboard / store products / API keys are provisioned (Phase-4 operator setup), an empty/unavailable Offerings fetch renders a graceful "Premium belum tersedia" state — never a crash, never a fake purchase. Keeps CI/sandbox green; the live purchase path is verified manually post-provisioning.
- **Wire the two dead-end CTAs to `PaywallRoute`**: the cap-dialog host and the search Premium-gate (`403`) host push the paywall with the appropriate entry-context. (The search `429` rate-limit state is a Premium-tier limit — a user who hits it is already Premium — so it is deliberately NOT routed to the paywall.)
- **Capture the proactive search upsell ([#253](https://github.com/aditrioka/nearyou-id/issues/253)) as an explicit deferred requirement** (positive statement + negative guard + tracking scenario) — the entitlement seam it needs ships here; the proactive-on-open behavior is the follow-up.

No Flyway migration; no backend change (the subscription contract is owned by [#291](https://github.com/aditrioka/nearyou-id/pull/291)). Not breaking.

## Capabilities

### New Capabilities
- `mobile-paywall`: the `PaywallRoute` / `PaywallScreen` / `PaywallViewModel` surface, the `:infra:revenuecat` `PurchaseController` purchase-and-entitlement seam, the Offerings-derived pricing model, the subscribe → return → re-evaluate flow, and the fail-soft unconfigured state.

### Modified Capabilities
- `mobile-cap-upsell-dialog`: § "Premium CTA navigation is deferred" changes from a dismiss-only placeholder to host-driven navigation that pushes `PaywallRoute` (entry-context = like cap). The dialog component stays navigation-free. Closes [#235](https://github.com/aditrioka/nearyou-id/issues/235)'s hook.
- `mobile-search`: the Premium-gate (`403`) "Aktifkan Premium" CTA navigates to `PaywallRoute` (entry-context = search gate) instead of being a no-op ([#254](https://github.com/aditrioka/nearyou-id/issues/254)); a new explicit requirement records the proactive-on-open upsell ([#253](https://github.com/aditrioka/nearyou-id/issues/253)) as deferred, with the reactive 403 gate retained. The `429` rate-limit state is unchanged (Premium-tier limit; no paywall CTA).

## Impact

- **New module**: `:infra:revenuecat` (KMP, RevenueCat SDK fenced here). `settings.gradle.kts`, `gradle/libs.versions.toml` (`purchases-kmp` pin), `dev/module-descriptions.txt` + `dev/scripts/sync-readme.sh --write`.
- **`:mobile:app`**: new `screens/paywall/` package (Screen + ViewModel + UiState), `screens/routing/NavKeys.kt` (+ `AppNavSerialization.kt` registration), `AppEntryProvider.kt` entry, the cap-dialog host wiring, the search Premium-gate host wiring, Koin DI for `PurchaseController` + `PaywallViewModel`.
- **`:shared:resources`**: new CMP string keys (benefit labels, period labels, savings/per-day format strings, CTA, disclosure, unconfigured-state copy); `SharedStringsCatalogTest` updated.
- **Contract dependency**: aligns to `subscription-billing-webhook` ([#291](https://github.com/aditrioka/nearyou-id/pull/291)) — `subscription_status ∈ {free, premium_active, premium_billing_retry}`, webhook-driven, no client read endpoint; the client premium signal is the RevenueCat SDK `CustomerInfo` entitlement.
- **Operator setup (out of this change, gates the live path)**: RevenueCat dashboard offerings/entitlements, Google Play / App Store products, and the RevenueCat **publishable client key** wired per-flavor via Android `buildConfigField` / iOS xcconfig (mirroring `SUPABASE_ANON_KEY` / `GOOGLE_SERVER_CLIENT_ID` — NOT a `secretKey()`/GCP Secret Manager slot, which is backend-only). #291's backend `revenuecat-webhook-secret` Secret-Manager slot is a separate concern owned by that change. The fail-soft state keeps the app correct until these land.
- **Issues**: closes [#235](https://github.com/aditrioka/nearyou-id/issues/235); addresses [#254](https://github.com/aditrioka/nearyou-id/issues/254); records [#253](https://github.com/aditrioka/nearyou-id/issues/253) as a tracked deferral.
