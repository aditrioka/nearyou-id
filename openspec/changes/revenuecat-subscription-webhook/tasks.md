## 3. Service (state machine)

- [x] 3.1 `SubscriptionService.process(event)` — one transaction per event: idempotency gate first (skip + signal duplicate when the event row already exists), then map event type → transition: `INITIAL_PURCHASE`/`RENEWAL` → `premium_active` (RENEWAL is unconditional — it heals a `premium_billing_retry` user back to active); `BILLING_ISSUE` → `premium_billing_retry` (+ 7-day `grace_end_at`); `EXPIRATION` → `free` (any reason — terminal); `CANCELLATION` → no status change. Write the `subscription_events` row in the same transaction. **Prefer a read-free `UPDATE users SET subscription_status … WHERE id = ? RETURNING` (0 rows = orphan) so no `SELECT … FROM users` is issued and `BlockExclusionJoinRule` does not apply.** If a `SELECT … FROM users` is genuinely needed, it WILL trip the rule in this non-admin code (no admin-path exemption) → carry `@AllowMissingBlockJoin` on the SQL-holding property (PR #207 pattern) with the privileged-by-id-billing-write rationale.
- [x] 3.2 Edge/deferred branches: orphan `app_user_id` (no matching user) → log WARN + `200`, no write; unknown event type → log + `200` ignored; `GRANT` → log + `200`, **no** status change and **no** entitlement (deferred-referral guard). `EXPIRATION` does **not** set `users.privacy_flip_scheduled_at` (deferred-privacy-flip guard); no time-based grace-elapse downgrade (deferred grace-state-worker guard).
- [x] 3.3 Notifications via the existing `NotificationEmitter`: `subscription_billing_issue` with `body_data = {grace_end_at}` on `BILLING_ISSUE`; `subscription_expired` with `body_data = {}` on `EXPIRATION`; none on `CANCELLATION` (deferred — no catalog type). Confirm both types are in the V10 `notifications.type` CHECK (they are).

## 5. Tests (docs/11 §5 DoD; kotest `@Tags("database")`, test pool `autoClose(hikari())` size 2)

- [x] 5.1 Auth: missing Bearer → 401; wrong Bearer → 401; **signature header present-but-malformed → 401** (distinct from absent); **no signature header → admitted on Bearer alone** (mandatory-prod-signing deferred guard); **valid OIDC token alone → 401** (fulfills the `internal-endpoint-auth` "Vendor-webhook route does NOT inherit OIDC" scenario for this route); correct Bearer (+ valid HMAC) → admitted. Plus a **source-scan test** that the Bearer + HMAC comparisons use `MessageDigest.isEqual` (no `==`/`Arrays.equals` on secret bytes) — mirror `AdminAuthConstantTimeScanTest` (PR-time, no `@Tags("database")`).
- [x] 5.2 Idempotency / envelope: first delivery records one row + applies status; duplicate `revenuecat_event_id` → `200` duplicate, single row, no re-apply; **concurrent identical deliveries (two `process()` racing the same `revenuecat_event_id`) → exactly one row, transition applied at most once**; malformed body → `400`, no writes; orphan `app_user_id` → `200`, no writes; unknown event type → `200`, ignored.
- [x] 5.3 State machine: `initial_purchase` → `premium_active` + event; `renewal` (from `premium_active`) → `premium_active` + event; **`renewal` from `premium_billing_retry` → `premium_active` (heals)**; `billing_issue` → `premium_billing_retry` + `subscription_billing_issue` notification (`grace_end_at`) + access retained; `expiration` → `free` + `subscription_expired` notification; `cancellation` → status unchanged + event + no notification; **`billing_issue`/`expiration` on an already-`free` user → safe no-op (event recorded, status stays `free`)**.
- [x] 5.4 Deferred guards: `GRANT` → no status change, no entitlement, `200`; `EXPIRATION` on a `private_profile_opt_in = TRUE` user → `free` AND `privacy_flip_scheduled_at` stays `NULL`; a `premium_billing_retry` user past the grace window with no `EXPIRATION` → NOT auto-downgraded; an unsigned request → admitted (mandatory-prod-signing not enforced in this change).
- [x] 5.5 Analytics: the MRR query (`source = 'paid' AND event_type IN ('initial_purchase','renewal')`) returns only the paid purchase/renewal rows after a mixed-event run.
- [x] 5.6 Transaction atomicity: a `BILLING_ISSUE` whose notification write fails (fake `NotificationEmitter` that throws) leaves `subscription_status` unchanged AND writes no `subscription_events` row (the single per-event transaction rolls back — the literal D3 guarantee).
