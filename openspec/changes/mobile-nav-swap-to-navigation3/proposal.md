## Why

`:mobile:app` navigates on **Voyager `1.1.0-beta03`** — a pre-stable pin the project accepted as a documented compromise. The [`gradle/libs.versions.toml`](../../../gradle/libs.versions.toml) comment says it plainly: *"Re-evaluate when Voyager cuts a stable 1.1.0."* That never happened — Voyager's `1.1.0` line has sat in beta since 2023 and its most recent release of any kind was an alpha in **2024** (~2 years stale). Meanwhile **Navigation 3** is now the official, Compose-first navigation direction from **both Google** (`androidx.navigation3`, stable since Nov 2025) **and JetBrains** (the Compose Multiplatform port `org.jetbrains.androidx.navigation3`, shipped for Android + iOS + desktop + web since CMP 1.10). The archived `mobile-app-scaffold-replace-wizard` `design.md` Decision 1 **pre-authorized this exact change**: *"If state-restoration becomes load-bearing later, a swap-from-Voyager is mechanical (one file per screen) and qualifies as its own change."* This is that change — and it's the cheapest it will ever be, because the surface is only 6 screens. Migrating now, before more screens land, avoids the compounding tech debt of building further on a stalled substrate and aligns with the project's Guiding Principle #1 ("standard frameworks over clever abstractions").

## What Changes

- **BREAKING (mobile-internal substrate swap)** — Replace `cafe.adriel.voyager:voyager-navigator` + `voyager-koin` with `org.jetbrains.androidx.navigation3:navigation3-ui` (pulls `navigation3-runtime` / `-common` transitively) + `io.insert-koin:koin-compose-navigation3` in [`gradle/libs.versions.toml`](../../../gradle/libs.versions.toml) and [`mobile/app/build.gradle.kts`](../../../mobile/app/build.gradle.kts). The JetBrains CMP port is **pre-stable (alpha)**; the exact version is pinned at `/opsx:apply` per the mandatory pre-implementation library re-check (this proposal's substrate research is dated 2026-06-05). No backend, DB, or API contract changes.
- **Nav host model** — `App()` swaps Voyager's `Navigator(RootRouterScreen()) { CurrentScreen() }` for Nav3's `NavDisplay(backStack, entryProvider, entryDecorators)` over a developer-owned `rememberNavBackStack`. Routes become typed **`NavKey`** entities (e.g. `RootRoute`, `SignInRoute`, `HomeRoute`, `AgeGateRoute`, `PostCreationRoute`) mapped to composables by an `entryProvider`. The 6 screens convert from Voyager `Screen` classes (`override fun Content()`) to plain `@Composable` functions.
- **Routing verbs** — `navigator.replaceAll(X)` → a back-stack list operation (clear + add, via a small `replaceAll` extension); `navigator.push(X)` → `backStack.add(key)`; `navigator.pop()` → `backStack.removeLastOrNull()`. `LocalNavigator.currentOrThrow` is replaced by hoisted navigation lambdas / the back stack passed into the `entryProvider`. **Observable behavior is preserved** (token-presence routing, auth-boundary back-stack clearing, FAB → composer, success → pop, process-death → SignInScreen) — only the mechanism changes.
- **iOS route serialization (new requirement)** — Nav3 cannot use reflection-based back-stack serialization on non-JVM targets, so all `NavKey` routes are `@Serializable` and registered in a polymorphic `SerializersModule` via `SavedStateConfiguration`, passed to `rememberNavBackStack`. This is what makes the back stack saveable on iOS.
- **Security: id_token stays out of the serialized back stack (new negative-guard requirement)** — The age-gate spec mandates the Google `id_token` be *"held in in-memory navigation state only (never persisted)."* Because Nav3's saveable back stack **does** serialize route keys on iOS, the `id_token` MUST live in an in-memory holder (e.g. `PendingSignupIdentity`), **not** as a property on `AgeGateRoute`. A negative-guard scenario asserts the serialized back stack never contains the token. The existing process-death contract (→ `SignInScreen`) is preserved: on restore, the in-memory identity is gone and the flow re-routes to sign-in.
- **State retention** — `NavDisplay.entryDecorators` wires `rememberSaveableStateHolderNavEntryDecorator()` so each entry gets its own `SaveableStateRegistry` (per-entry `rememberSaveable` state — e.g. the composer draft, the location-gate state machine — is scoped and retained across config changes while the entry is in the back stack). Per-entry ViewModel scoping (`rememberViewModelStoreNavEntryDecorator()` + the `org.jetbrains.androidx.lifecycle:lifecycle-viewmodel-navigation3` artifact) is **deferred** — every current screen is stateless and resolves singletons via `koinInject`, which is unaffected by the nav swap; the decorator + artifact land with the first ViewModel-backed screen.
- **Nav-model placement (no allowlist change)** — The Nav3 model (route `NavKey`s, the `entryProvider`, the polymorphic serialization module, the back-stack `replaceAll` helper, and the `PendingSignupIdentity` holder) lives under the **already-carved-out `screens/routing/**`** path — the same carve-out that today houses `RootRouterScreen` + `SessionExpiryEffect`. Because route keys that name auth-flow identifiers (`SignInRoute`, `AgeGateRoute`) and the identity holder land in an existing allowed path, the `mobile-app-scaffold` auth-identifier allowlist needs **no modification** (chosen over a dedicated `navigation/` package + allowlist extension to avoid restating a long, scenario-dense requirement).
- **Tests** — Migrate the 12 nav-dependent test files from the Voyager `Navigator(Screen())` harness to the Nav3 `NavDisplay` / back-stack harness: 7 Robolectric `*ScreenTest`, 4 iOS `*FlowIosTest`, and the commonTest `HomeScreenTest` smoke (deleted — its Voyager-`Screen` `.key` API is gone, render coverage already lives in `NearbyTimelineScreenTest`). The 5 pure `*UiStateTest` have no nav dependency and are confirmed untouched. Add a serialization round-trip test for the polymorphic `NavKey` module, the id-token-not-serialized negative guard, and an `AgeGateFlowIosTest` restored-back-stack case for the process-death guard.
- **Docs + catalog hygiene** — Amend [`docs/04-Architecture.md`](../../../docs/04-Architecture.md) (the "Voyager nav" lines) to "Navigation 3," and replace the Voyager pin-rationale comment in the version catalog with the Nav3 pin rationale.

**Deferred to named follow-ups** (NOT in scope): adaptive multi-pane Scenes / list-detail layouts (no tablet target yet — `mobile-nav3-adaptive-scenes`); the future Nearby/Following/Global tab host with multiple back stacks (`mobile-home-tab-host`, already forward-referenced by `mobile-post-creation`); Nav3 `ResultEventBus`-based cross-screen results (the deferred Nearby-refresh-on-return already has its own follow-up); deep-link routing (Nav3 `DeepLinkRequest`, post-MVP).

### Modified Capabilities
- `mobile-app-scaffold`: the "Typed navigation host with start destination" requirement is re-expressed from Voyager (`Navigator` + `Screen`) to Nav3 (`NavDisplay` + `NavKey` + `entryProvider` + developer-owned `rememberNavBackStack`); **ADDS** an iOS polymorphic-`NavKey`-serialization requirement and an `entryDecorators` per-entry-state-retention requirement. (The auth-identifier allowlist is unchanged — the nav model lives under the already-carved-out `screens/routing/**`.)
- `mobile-auth-signin`: three requirements re-expressed on the Nav3 back stack — "SignInScreen renders Google Sign-In entry point" (`Screen` → composable keyed by `SignInRoute`), "Backend error codes are mapped to user-facing copy with no fallthrough" (the 404→age-gate path now **sets `PendingSignupIdentity` + appends `AgeGateRoute`** instead of "carrying the identity via the navigator" — the load-bearing reconciliation with the age-gate holder design; plus `200`→`HomeRoute` wording), and "RootRouterScreen routes based on token presence" (`Navigator(startDestination)` → seeded `rememberNavBackStack`; `replaceAll(...)` → back-stack clear+set). Observable token-presence routing, error-code→copy mapping, and the splash/Banned-restart scenarios are unchanged.
- `mobile-age-gate`: the `AgeGateScreen` (Voyager `Screen` → composable keyed by `AgeGateRoute`), the "reuses the verified Google identity" requirement (id_token via an in-memory holder, not a serialized NavKey), the "Account-exists collision routes to sign-in," and the "Process death on AgeGateScreen routes to SignInScreen" requirements are re-expressed in Nav3 terms; **ADDS** the negative-guard that the serialized back stack never carries the id_token.
- `mobile-nearby-timeline`: the `NearbyTimelineScreen` (navigation-free; Voyager `Screen` → composable) and the "HomeScreen hosts NearbyTimelineScreen and routing is unchanged" requirement are re-expressed (`HomeScreen` keyed by `HomeRoute`; "routes to `HomeScreen`" → "routes to `HomeRoute`").
- `mobile-post-creation`: four requirements re-expressed — "PostCreationScreen renders the composer surface" (`Screen` → composable keyed by `PostCreationRoute`), "A home-surface FAB opens the composer…" (`navigator.push(...)` → `backStack.add(PostCreationRoute)`), "Screen state mapping covers loading, success, and each error…" and "Successful post returns to Home…" (`navigator.pop()` → `backStack.removeLastOrNull()`); the "no cross-screen reload signal" negative guard is updated to also forbid a Nav3 `ResultEventBus` reload signal.

## Impact

- **Module `:mobile:app`** — `App.kt` (nav host), the `screens/routing/` package gains the Nav3 model (NavKey routes + `entryProvider` + polymorphic `SerializersModule` + back-stack `replaceAll` helper + the `PendingSignupIdentity` holder, alongside the existing `RootRouterScreen` + `SessionExpiryEffect`, both back-stack-driven now), all 6 screen files (Voyager `Screen` → `@Composable`), `di/MobileModule.kt` (register `PendingSignupIdentity`; preserve all existing bindings), `build.gradle.kts` (swap nav deps; the Release-variant `*ScreenTest` exclude list stays). 12 nav-dependent test files migrated/removed + 5 pure `*UiStateTest` confirmed untouched + 2 new standalone tests (serialization round-trip, id-token-not-serialized guard) + new process-death-guard cases (Robolectric + an `AgeGateFlowIosTest` restored-stack case).
- **`gradle/libs.versions.toml`** — remove `voyager` version + `voyager-navigator` / `voyager-koin` libraries; add `navigation3` (JetBrains CMP) + `koin-compose-navigation3`. **Substrate change → triggers the pre-implementation library re-check at `/opsx:apply`.**
- **Backend / DB / API** — none. Pure mobile-side substrate swap; no migration, no endpoint, no staging deploy. (Pre-archive smoke = N/A; the gate is the Android `assembleDebug` + iOS framework-link + lint/test suite.)
- **Docs** — `docs/04-Architecture.md` § Mobile Status "Voyager nav" → "Navigation 3" (amended in this change, since the change deliberately supersedes the prior canonical statement).
- **Invariants** — the mobile-strings invariant (no hardcoded UI strings) is preserved (no copy changes); the auth-identifier carve-out is extended (reviewer-checked); the id_token-never-persisted privacy contract is preserved and newly guarded against the iOS serialized back stack. No backend invariants are touched.
- **Verification** — platform nav actuals (iOS back-stack restore across process death) are not commonTest-unit-testable; a manual Android-device + iOS-sim pass (auth-boundary routing, FAB→composer→pop, process-death → SignIn) is the runtime check alongside the Robolectric / commonTest / serialization suites.
